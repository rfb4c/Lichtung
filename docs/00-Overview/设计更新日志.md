## 待实施设计决策（已讨论，尚未开发）

### 右侧栏重设计（讨论日期：2026-03-10）

**背景**：原右侧栏完全模仿 Twitter（热门话题、关注推荐），所有元素均无实际功能，与研究目标无关。

**决策结果**：

| 元素 | 决策 | 说明 |
|---|---|---|
| 搜索框 | ✅ 保留并实现 | 按 Topic 名称搜索，回车确认，筛选主 Feed |
| 热门话题卡片 | ❌ 移除 | 与研究目标相悖，不应强化已有热点 |
| 关注推荐 / Follow 按钮 | ❌ 移除 | 与平台定位无关 |
| Show more | ❌ 移除 | 无内容支撑 |
| **冷门话题入口** | 🔜 占位保留，未来实现 | 见下方 |

**搜索交互规范**：
- 搜索对象：`topic.name`（议题名称，如 "Gun Control"）
- 触发方式：按 Enter 确认
- 效果：主 Feed 只显示该 Topic 下的报道
- 重置方式：点击侧边栏 Home 按钮回到全部 Feed（无需额外"清除"按钮）

**冷门话题（未来功能）**：
- 设计动机：主动引导用户接触关注度较低的议题，增加信息多样性，符合降低感知极化的研究目标
- 定义待定：候选方案为"评论数/报道数最少的 Topic"，或手动标记
- 交互方式：点击后与搜索筛选效果相同（筛选 Feed）
- **当前阶段**：仅保留 UI 入口（占位卡片），不实现筛选逻辑

### FeedItem 动作按钮重设计（讨论日期：2026-03-10）

**背景**：原动作栏完全模仿 Twitter，转发/点赞/浏览量显示伪随机数字，全部无功能。

**各按钮决策**：

| 按钮 | 决策 | 说明 |
|---|---|---|
| 评论 | ✅ 保留（已实现） | 展开评论区，计数真实 |
| 转发 | ❌ 移除 | 平台无发帖功能，无意义 |
| 点赞 | ❌ 移除 | 伪随机数字，无实际功能 |
| 浏览量 | ❌ 移除 | 伪随机数字，无实际功能 |
| ··· 更多菜单 | ❌ 移除 | 无内容支撑 |
| **收藏** | 🔜 保留按钮，暂不实现 | 与 Bookmarks 功能联动，未来实现 |
| **分享** | ✅ 实现（思路 A） | 见下方规范 |

**分享功能规范**：
- 分享对象：报道的**原始外部链接**（`report.url`），不是平台内链接
- 实现方式：优先调用 `navigator.share`（移动端系统分享菜单）；不支持时 fallback 到复制链接到剪贴板 + toast 提示"链接已复制"
- 前置条件：`report.url` 必须是有效的外部链接（静态数据需确认）

### 未来功能规划（讨论日期：2026-03-10）

以下功能已形成方向共识，暂不实现，仅作规划记录：

**Bookmarks（收藏报道）**
- 研究价值：用户收藏内容可反映信息偏食程度，是衡量信息茧房的潜在数据来源
- 在 Profile 页展示"收藏的报道"列表，按 Topic 分组

**Following → 关注 Topic**
- 重定位：不关注人，而是关注议题（Topic）
- 研究价值：用户主动订阅议题的选择行为，可作为干预效果的测量指标
- 实现后影响 Feed 排序：关注的 Topic 优先展示

**Notifications（通知）**
- 与评论回复功能联动（前置依赖：嵌套评论）
- 触发场景：有人回复了你的评论

**评论回复功能（嵌套评论）**
- 目前只有顶层评论，未来实现嵌套回复，是 Notifications 的前置依赖

**信息饮食透明度（Information Diet）**
- 研究价值：**高**，直属感知极化干预范畴，有文献支持（元认知干预）
- 展示用户本次访问浏览了哪些 Topic 的报道，如"你今天浏览了 Gun Control (5篇)、Climate Policy (2篇)"
- 位置候选：右侧栏下方 / Profile 页
- 实现前置条件：需要浏览行为记录（前端 sessionStorage 或 Supabase 行为日志）

**Explore → 议题探索页**
- 研究价值：**中-高**，鼓励用户主动接触不熟悉的议题
- 展示所有 Topic 的卡片列表，每张卡片显示议题名、报道数、简介
- 点击进入该 Topic 的筛选 Feed

**先评论后看评论（Comment-First）**
- 研究价值：**高**，成本**低**
- 用户展开评论区时，先显示输入框；点击"查看评论"后才加载其他人的评论
- 减少从众效应，帮助用户形成独立判断，直接对抗评论区回音壁造成的感知极化

**Discover New Topics（冷门话题）**
- 右侧栏占位已实现，筛选逻辑待实现

## v0.4.3 — Demo 录制版改动回流 + Supabase 数据同步 (2026-08-15)

### 变更内容

来源：录制仓库 `C:\docs\workplace\Lichtung`（分支 `feature/demo-narration`）。demo 视频录制期间在那边直接改的应用代码与数据，此次回流到主线；录制工程本身（Playwright 录制脚本、Remotion 幻灯片、素材/录音/录屏）不回流，继续留在录制仓库。

**Path A 排序简化（feedSorter.ts）**
- 移除敌意降权：`hostilityScore ≥ 0.4` 的位置惩罚公式、以及"每 4 条保证 1 条反刻板印象内容"的兜底窗口全部删除
- 现行逻辑：反刻板范例（`counterStereotypical`）整体置顶，组内保持 engagement 排序
- 类型层同步删除 `Report.hostilityScore` 与 `Report.contentType`
- ⚠️ `app-data.json` 中这两个字段的值仍在，未清理，运行时不再读取

**分布图比例修复（DistributionChart.tsx）**
- 条宽从 `percentage / max(distribution) × 100` 改为直接取 `percentage`
- 原逻辑会把最高档永远拉满整条宽度，视觉上夸大档位之间的差距——这与 Path B "如实呈现分布"的前提直接冲突

- 未配置 Supabase 时，用 `mockUsers[].email` 匹配登录（密码忽略），登录态存 localStorage

- 这条让"零配置克隆即可演示 Path C 登录视角"成立

**sticky 修复（App.module.css / index.css）**
- `overflow-x: hidden` → `clip`。hidden 会创建滚动容器，导致侧边栏 `position: sticky` 失效（主题开关跟着页面滚走）

**静态数据（app-data.json）**

## v0.1.0 — Feed 流 + 光谱可视化 (2026-02-14)

### 功能
- Twitter 风格 Feed 流（3 列布局：侧边栏 + 600px 主 Feed + 右侧栏）
- 事件 + 报道数据模型（3 个事件，29 篇报道）
- SpectrumBar 光谱条（路径 B：共识数据可视化）
- 悬停 500ms 延迟显示分布 Tooltip，300ms 淡出
- 深色/浅色主题切换（localStorage 持久化）
- Supabase 集成（events + reports 表），回退到静态 JSON
- 报道卡片：图片、来源标识、立场标签、链接卡片
- 思源宋体 + 文字 Logo
- 自定义 Favicon
- Lucide 图标库

### 数据库
- `events` 表（id, title, supportive, neutral, opposed）
- `reports` 表（id, event_id, title, summary, source, stance, image_url, published_at）
- RLS 策略：公开只读
