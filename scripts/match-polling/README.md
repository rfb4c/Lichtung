# 报道 → 民调 匹配管线（Path B）

判定一篇报道的核心命题，是不是某条民调正在问的那件事。产出写进
`report.pollingDataId`，供 `src/lib/pollingResolver.ts` 读取——**该文件不需要改动**，
本管线只是把此前人工填写的那个字段改为可审计的产出。

代码结构照搬 `scripts/annotate/`（Path A 标注管线），两者的运行方式与出错行为一致。

## 判据

**命题对齐，不是议题相同。**

```
精确匹配 = 报道的核心主张，就是民调问题在问的那件事本身
偏松/该拒 = 报道只是同一个大议题下的相关新闻，没有直接回答民调的问题
正确的 null = 议题下没有一条民调在问报道真正讲的那件事
```

「不挂」是有意义的答案，不是数据缺口。**覆盖率是结果，不是指标**——把提高挂载率
当目标去调判据，会重新引入「同议题就硬挂」的老毛病。

完整判据（喂给模型的那一份，英文）在 `prompts/path-b-match.md`。判据里的举例
刻意用了语料之外的议题（最低工资），以免把语料里的正确答案直接写进提示词。

## 裁决规则（事前写定，无人工干预）

```
两个 judge 都判 null                  → 不挂
两个 judge 落在同一个「问题组」        → 挂该组里最新的那条
其余一切（含一方 null、分属不同组）    → 不挂
```

**分歧即不挂**，与 Path A「分歧取 0.5」是同一种克制：两个独立 judge 对命题是否
对齐都谈不拢，本身就说明对齐关系不清晰。不挂只是不显示图表；挂错会把一份回答
别的问题的分布摆在读者面前，那与 Path B 想做的事正好相反。

**年份不参与一致性判定。** 同一道题的不同年份版本（如 2024 与 2026 两条堕胎合法性
民调）在命题上无法区分，要求两个 judge 在年份上达成一致既不可能也不必要。它们由
`pollGroupKey()` 归为一组，组内取哪条由 `pickPollInGroup()` 按确定性规则决定，
不经过模型。

## 用法

```bash
npm run match:mock              # 假 judge，不联网不花钱，验证管线本身
npm run match -- --limit 3      # 冒烟，确认两边都通、schema 都被接受
npm run match                   # 全量 28 篇 × 2 judge = 56 次调用
npm run match:merge             # 裁决 + 打印与现状的差异，不写 app-data.json
npm run match:merge -- --apply  # 核对差异后再写回
npm run match -- --resume       # 中途失败后只补跑缺的条目
```

需要两把密钥，写进仓库根目录的 `.env`（已在 `.gitignore`）：

```
ANTHROPIC_API_KEY=...
OPENAI_JUDGE_MODEL=...
OPENAI_API_KEY=...
```

`OPENAI_JUDGE_MODEL` 不要凭记忆填——跑 `npm run annotate:models` 从 API 拉当前账号
可用的型号列表来确认。这个值会进 `poll-matches.json` 的 meta 并被论文引用。

**`match:merge` 默认是 dry run。** 不加 `--apply` 只打印差异、不动 `app-data.json`。
摘除挂载（现在有图表、写回后没有）是风险最高的一类改动，会单独列出并加警告；
逐条核对 `poll-matches.json` 里两个 judge 的 `rejection` 字段再决定。

⚠️ **mock 产物不要提交。** `npm run match:mock` 会写出一份 `poll-matches.json`，
内容只是 reportId 的哈希，毫无意义。跑完删掉，别误当成实跑结果。

## 出错路径

与标注管线同款的几道闸：

| 闸 | 挡的是什么 |
|---|---|
| `--judges` 拼错即拒绝 | 拼错一个字母就开始花钱 |
| 首发失败即中止 | 密钥/型号/schema 出错时，不把剩余 54 次调用打出去 |
| `--resume` 核对配置哈希 | 判据或型号变了还续跑，会把两份来源混进同一个文件 |
| 失败即非零退出 | `match && merge` 链式跑时，半份判定不许流进裁决 |
| **候选外 id 即判失败** | 本管线特有：候选清单逐篇不同，schema 约束不了「id 必须在候选里」。编出来的 id 会一路流到 `pollingDataId`，在前端变成查不到的引用，图表静默消失 |

## 两处刻意的设计取舍

**judge 适配器与标注管线重复而不共用。** `lib/judges/` 下的三个适配器与
`scripts/annotate/lib/judges/` 结构相同。共用需要把那边改成泛型，而 Path A 的
判定路径已实跑、结果已被论文引用——冻结它比消除这点重复更重要。真正通用且无
歧义的两个函数（`.env` 解析、内容哈希）仍从标注管线 import，不重复实现。

**Judge A 用 `claude-opus-5`，与 Path A 的 `claude-sonnet-5` 不同型号。** 任务性质
变了：三属性标注是对单篇报道逐条打勾，这里要在一篇报道与多条候选题干之间做比较
判断，且「相邻命题」是最容易出错的一类。两条管线的型号都写在各自产物的 meta 里，
论文按管线分别声明即可，不必强行统一。
